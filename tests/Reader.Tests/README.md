Run `dotnet run --project tests/Reader.Tests/Reader.Tests.csproj` from the plugin repository.

The executable links the production page-turn lifecycle, input, layout, frame and renderer sources. Drawing adapters record page indexes, rectangles, strip transforms, tints and gradient shadows. A synchronous control adapter exercises automatic navigation, gesture completion and animation takeover.

Checks cover both reading directions, covers, boundaries, neighboring layouts, different image sizes, excessive drag distance, shadow clipping/fading, automatic animation convergence, cancellation, short flicks, two-finger pan/pinch and pointer transitions.

Wide-page checks cover splitting into ordered half pages, pairing across image boundaries, logical page navigation, late dimensions, mode changes, enabling/disabling splitting while preserving the current image, source insertion, odd image widths, cropped flat/curled/diagonal rendering, and shared bitmap loading. The reader setting to split wide images defaults to enabled. When enabled, spread modes split images whose aspect ratio is at least 1.6 times the sampled portrait-page median (minimum 1.0); without portrait samples the threshold is 1.2. Disabling the setting, single-page mode and vertical mode keep the original image whole. Progress shown in the reader counts half pages; plugin progress callbacks retain original image indexes.

The split scope defaults to global (local and network images) and can be limited to local files. Locality comes from the original loading strategy (`IsLocalSource`), not its disk cache path; custom strategies default to non-local and can opt in. Scope checks cover cached network images, both reading directions, focus preservation on scope changes, and the split toggle/mode taking precedence. The settings description states that splitting only applies in double-page mode and increases loading time.

Diagonal page-turn checks cover all four drag directions in both spread modes, slanted texture and shadow geometry, paper coverage and shared strip edges, release/takeover continuity, canceled gestures, and flat completion. Drawing adapters record polygon fills and image-brush transforms; they do not validate native rasterization or GPU performance.

Chapter-navigation checks exercise the production command, wheel and pointer handlers in vertical, single-page and spread modes. They verify that arriving at a boundary is silent, continuing beyond it requests the matching chapter, the final spread is treated as a unit, tall vertical pages must reach their content edge, and canceled/zoomed/multi-pointer gestures remain silent. WinUI input adapters supply event data; popup bindings and native event routing are not simulated.

Concurrent frame handoff checks link the production drawing and image-window entry points. They pause the completion callback while a worker starts drawing or updating the cache, then verify that forward/backward automatic and gesture turns draw only the target spread and retain its bitmap instances.

Image-loading checks link the production disk cache, window controller, load service and background pipeline. A fake HTTP handler and real temporary files verify streaming, URL deduplication, corrupted-cache recovery, interrupted/canceled body cleanup and retries. Strategy/decoder adapters verify Hook compatibility, late dimensions, byte/bitmap ownership, canceled result rejection, mutable page indexes, queue pressure and pipeline restart. The cache validator uses a synthetic payload. The full Windows build verifies integration; native codec behavior is not simulated here.

A nonzero exit code means a regression. Native WinUI bindings, dispatcher scheduling, image codec behavior and GPU appearance must also be checked in a real reader window.

On Windows, also run `dotnet run --project tests/Reader.Storage.Tests/Reader.Storage.Tests.csproj`. This harness links the production local-file strategy and uses real WinRT storage APIs against temporary extracted ZIP pages. It covers legacy paths with mixed separators, nested chapters, Chinese names, spaces and literal `#`/`%` characters, image properties, byte preloading, normalized paths, StorageFile sources, cancellation and missing files. It does not require app installation; packaged application URIs, the app-local size cache and reader rendering still need verification in the application.

The independent `BuildPageIndex` setting defaults to enabled and is captured on the first source batch after opening a chapter. Changes apply on the next open. When disabled, the reader skips whole-chapter dimension probes and opens after the source list arrives; visible images and nearby preloads still load on demand. Automatic splitting remains independent, so page totals may change as dimensions arrive. Toggling splitting or its scope rebuilds the logical page sequence using known dimensions without restarting chapter probing or clearing the dimension cache. Optional-index checks cover both spread directions, restoration before dimensions are known, on-demand decoding, deferred splitting, reuse of dimensions after toggling splitting, and settings changes across chapter resets.

Page-index preparation checks exercise a 1,200-image chapter through the bounded size pipeline, failed/unknown dimensions, chapter replacement, saved-position mapping after all known splits, and navigation/render suppression while preparing. The reader publishes its initial page count and restored position after the full source batch has completed dimension probing. Network images without cached dimensions remain whole-image placeholders until their normal on-demand load supplies dimensions; preparing the index does not download the entire chapter.

Local image dimensions are persisted under the app's local cache (`reader_index/local_image_sizes.json`). Reopening validates file path, length and modification time, then reuses dimensions without calling the image-property reader. Page order, reading direction and the split setting are still applied to the current source list. Cache checks cover fresh cache instances, changes during/after a probe, invalid dimensions, cancellation, corrupt/unwritable storage, atomic publication, and reopening a chapter with only one changed file. The cache holds at most 20,000 source entries and never stores decoded bitmaps. The preparation indicator is delayed by 150 ms to avoid flashing during quick cache validation.
